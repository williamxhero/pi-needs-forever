pi-nf 架构：模块、时序、状态

Pi 会干活，Pi-Durable 记得住，pi-nf 判断什么时候继续、什么时候算完成，V 做最后验收。

A 执行者

真正干活：改代码、跑命令、用工具；模型由 Provider（P）提供。它只能说“我做完了”，没有最终判定权。

B 监督者

持有合同、状态、证据、投递、恢复和限额。它决定下一步，不替 A 干活。

C 裁判

只看 B 给的证据，判 CONTINUE / DONE / WAIT_EXTERNAL。Judge 通过 P 调模型，但没有工具，不能改文件、跑命令。

不同 Agent Harness，模块来源不同：Pi-Durable 已经提供的（Harness / tasks / docs / submissions / storage），pi-nf 直接用；Codex 没有这一层，所以 task / state / delivery / recovery / verification 由 NF 的 B 组自己补。

Provider 是基础设施，不属于 A / B / C / V：它包含 Models，Pi 和 Judge 只是调用它。当前可以是 CPA，也可以是 OpenAI、OpenCode 或其他兼容服务。

V 是独立验收，不属于 A / B / C：B 触发它，但它不是 A 的工具循环，也不是 C 的判断。

A 用 Pi（通过 P 调模型） B 用 Pi-Durable + pi-nf C 用 pi-nf（Judge 用 P） V 独立验收 P Provider（基础设施）
